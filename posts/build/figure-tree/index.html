Why a tree becomes unbalanced

Replay insertions to see how input order changes a binary search tree and why a heap stays shallow.

These figures replay comparisons and movements recorded during real insertions. The current node uses the accent colour, with the compared values beside it. Traversed edges remain thicker.

Insertion order determines height#

A binary search tree compares each new value from the root down until it finds an empty position. Both examples insert the same eleven values. Comparisons take the same time, so an earlier finish reflects less work.

Height determines worst-case search cost. Self-balancing trees such as AVL and red-black trees control that cost even when sorted input is common.

Search cost follows the path height#

A heap stays shallow regardless of insertion order#

A max heap adds a value to the next available leaf, then swaps it upwards while it exceeds its parent. Filling positions from left to right keeps the tree complete, including for sorted input.

A shallow heap does not provide the same ordering guarantee as a search tree. Each parent exceeds its children, but siblings and separate subtrees need not be ordered. A heap makes the maximum easy to retrieve; it does not make an arbitrary value as easy to find as in a balanced binary search tree.
